[01] overview

A crowd you can hide in, from day one.

zkSI is noise mining for private SI requests.

A fixed volume of traffic hides the real requests. When real traffic is low, miners fill the gap with decoy requests. When real traffic grows, the decoys shrink. PLANNED

The problem it targets: a private network is only as private as its crowd. With 50 users, there is no crowd. zkSI pays for the crowd until real users replace it. PLANNED

[02] how it works

A fixed target. Miners fill the gap.

The network aims for a fixed target volume, for example 1,000 requests per minute. The real value is not decided. PLANNED

Miners deliver the difference between the target and real traffic, and are paid for that volume. PLANNED

Noise matters most at the start and falls on its own as the network grows. What happens when real traffic goes above the target is not decided. [VERIFY]

The Noise Pool pays mainly for endpoint noise, because that is where the cost is. PLANNED

In the Noise Lab (v0.1), a local decoy generator hides your request among decoys and pads every request to a fixed size class (256 B, 512 B, 1 KB, 2 KB or 4 KB), so size does not reveal which one is real. It runs only in your browser and sends nothing. v0.1 LOCAL

Next, the same code becomes an open-source client that sends real requests through a partner gateway, and each user pays for their own noise. PLANNED

Decoys only work if they look like real requests. A generator that does not copy real request patterns can be detected. See risks.

What zkSI does not hide

The SI provider still reads the content of your real request. If your prompt contains your name, your email or text that only you would write, noise does not protect you. zkSI hides which request is yours, not what it says.

[06] proof of noise

Pay for decoys nobody can see.

Miners are paid for decoys that, by design, look like everything else. Proof of noise is how the network checks they were sent without learning which ones they were. The lab runs steps 2 to 4 locally today; the rest comes with the network.

  1. stakeThe miner locks a stake, for example 0.1 ETH. PLANNED
  2. commitAt the start of each one-hour epoch, the miner publishes on chain a hash of the batch it is about to send. v0.1 LOCAL on chain: PLANNED
  3. sampleAt the end, the hash of a future block picks about 1% of the batch. Nobody knows the sample in advance. v0.1 LOCAL block hash: PLANNED
  4. openThe miner reveals the sampled decoys. Two checks: they were sent (their nullifier shows up at the gateway) and they look credible. v0.1 LOCAL (hashes only) nullifier check: PLANNED
  5. pay or slashPass: paid for the whole batch. Fail: the stake is lost. PLANNED

Why 1% can be enough

If a miner fakes part of a batch, every opened decoy is a chance to get caught. With 100 decoys opened:

share fakedchance of being caught
5%99.4%
2%86.7%
1%63.4%

ESTIMATE  math: 1 - (1 - share)^100. Small cheating is harder to catch than big cheating. The batch size per miner and the audit size are not decided. [VERIFY]

Open questions

  • Who decides that a decoy is credible, and how. [VERIFY]
  • Whether a block hash is random enough, given that block producers can influence it. [VERIFY]

In the lab today. The Noise Lab runs a local version: a SHA-256 commit over the decoy hashes, then it opens ~1% (at least one), chosen from hash(commit + simulated beacon). It only checks hashes. v0.1 LOCAL

v2. The audit becomes a zk proof: the miner shows that k of the published nullifiers are theirs, without saying which. PLANNED

[08] cost of privacy

Privacy costs real inference.

An endpoint decoy is a real request to a real model, so it costs what a real request costs. We say this up front.

At network level, per hour

With a fixed target of 1,000 requests per minute, the decoys to pay for depend on how many real requests there are:

[09] cryptography

Commit first. Open later.

The core of proof of noise is a commitment: the miner fixes the batch with a hash before anyone knows which decoys will be opened. Changing a single character afterwards changes the hash, so it shows. The lab does this today; on chain it comes with the network. v0.1 LOCAL

This is the code the figure runs:

const sha = async s => hex(await crypto.subtle.digest("SHA-256", enc(s)));

const leaves = await Promise.all(batch.map(sha));   // one hash per decoy
const commit = await sha(leaves.join(""));          // published before sending

// later: a beacon nobody knew in advance picks what gets opened
const pick = parseInt((await sha(commit + beacon)).slice(0, 8), 16) % batch.length;

// anyone can check the opened decoy against the commit
const ok = (await sha(batch[pick])) === leaves[pick]
        && (await sha(leaves.join(""))) === commit;

[11] risks and limits

Open problems, written down.

None of these are solved. Each has a planned answer, and each answer still has to be tested.

RK.01OPEN

self-dealing

A miner who also runs a gateway could "send" decoys to itself and get paid for nothing.

planned answer: decoys go to several gateways at random, and gateways stake too.

RK.02OPEN

noise detectors

A provider can train a model to spot decoys. This becomes an arms race, not a one-time fix.

planned answer: the decoy generator copies real request patterns and is updated over time.

RK.03OPEN

provider terms

Automated fake traffic to closed SI providers may break their terms of use.

answer: start on open-source models run by partner gateways. DECIDED

RK.04OPEN

cost

Endpoint decoys cost real inference. If funding dries up, the noise level drops and so does privacy.

planned answer: fee on real requests plus a bootstrap fund, with the cost shown openly.

Limits

  • zkSI hides which request is yours, not what it says.
  • v0.1 does not send your request to any SI model, so it does not protect a real request yet. It shows the mechanism, locally. v0.1 LOCAL
  • It is not "100% anonymous", and nothing here is unbreakable. Do not rely on it for anything where a leak could hurt you.
  • The lab's decoys come from fixed templates; a trained detector could spot many of them. v0.1 LOCAL
  • The lab's audit only checks hashes, and its timings are simulated. v0.1 LOCAL
  • The mixnet is not chosen, so the network layer's real protection is unknown. [VERIFY]
  • A block hash as randomness may be biased by block producers. [VERIFY]

[14] faq

Short answers.

Is there a token?

Yes: $ZKSI, on Robinhood Chain (launch: 21 Oct 2026, 5 PM UTC). It does not run the network yet and its role is not decided. The contract address comes only from @0x_zkSI on X; anything else using the zkSI name is not ours. DECIDED

What runs today?

v0.1 · local only. The Noise Lab runs today in your browser: decoys, fixed size classes, random timing, commit and audit. The network comes next: no miners, gateways or contracts yet. v0.1 LOCAL

Does the lab protect my real requests today?

No. v0.1 does not send your request to any SI model. It shows the mechanism locally, so you can test it without an account or an install. v0.1 LOCAL

Is the code public?

The lab's code is: github.com/zkSI0x/noise-lab, under MIT. v0.1 LOCAL

Does the lab send what I type anywhere?

No. It runs 100% locally and makes no network request after the page loads. You can check it yourself, see verification. v0.1 LOCAL

Will zkSI hide what I write?

No. It is meant to hide which request is yours, not what it says. If your prompt names you, noise does not help. See section 04.

Is it 100% anonymous?

No, and we will not say it is. The open problems are listed in risks and limits.

Why do decoys cost money?

Endpoint decoys are real requests to real models, so they cost real inference: ~$0.001-0.005 each on a cheap model, ~10x on a top model. See cost of privacy. ESTIMATE

Which models will it use?

Open-source models run by partner gateways. Automated decoy traffic to closed SI providers may break their terms. DECIDED

Can I mine now? How much would I earn?

No one can mine yet: the network comes next. Miners would be paid per verified decoy from the Noise Pool, and rewards are not guaranteed. PLANNED

Someone from zkSI messaged me. Is that real?
